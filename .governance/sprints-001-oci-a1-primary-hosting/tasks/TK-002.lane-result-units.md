## Done-criteria mapping

- Complete: web unit contains the required ubuntu identity, Node 22 PATH/start command, tailnet API base URL, memory cap, Node heap cap, journal logging, and docker ordering/dependency.
- Complete: backup service/timer use `ubuntu`, `UMask=0077`, the existing backup script, and a 01:10 UTC schedule before 01:41 UTC.
- Complete: health service/timer run every minute with the requested tailnet URLs, restart disabled, and the alert sink set as `JETSCOPE_BUS_WRITE`.
- Complete: the sink stores per-component state and the failed, failed, recovered simulation produced exactly two alerts and ended in `ok`.
- Not run locally: the task card's `systemd-analyze verify` requires an oci-a1/systemd environment; no remote access was performed by design.

## Known risks

- `health-check.sh` hard-codes `/var/log/jetscope-health.log` and does not expose a log-path environment variable. The health service uses `LogsDirectory=jetscope-health` plus `BindPaths=/var/log/jetscope-health:/var/log` so that path resolves to an ubuntu-writable systemd-managed directory within the service mount namespace; this should be confirmed by `systemd-analyze verify` and a local oci-a1 timer run during installation.
- The alert sink accepts the current simple JSON emitted by `health-check.sh`; it intentionally does not introduce a JSON-parser dependency.
